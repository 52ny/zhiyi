# ADR 0001：保持纯静态多文件架构，暂不引入打包器

- 状态：已采纳
- 日期：2026-10-23

## 背景

项目需要部署到 GitHub Pages，用户打开即用；参赛演示要求现场零安装、可离线。现有实现由 16 个浏览器脚本组成，按顺序装配到 `window.ZY`。

## 决策

短期保留“原生脚本 + 顺序装配”的运行时形态，不引入 React/Vue 或打包器；工程化通过工具链补齐：

- ESLint 静态检查
- Vitest 单元测试（jsdom）
- 自定义 `verify` 脚本校验语法、资源引用、manifest 与 SW 预缓存
- GitHub Actions 执行 `npm run check`

## 理由

1. 静态文件可直接发布，构建链故障不影响线上。
2. 迁移成本低，现有功能无需重写。
3. 比赛评分更看重完整度、文档与稳定演示，而非框架。

## 代价

- 无模块打包与 tree-shaking，脚本按需加载能力弱。
- 全局命名空间需要约束，类型安全不足。

## 后续

按“绞杀者模式”逐步把 `core/`（db、ai、importer）迁移为 ES Module，并引入 JSDoc + `tsc --checkJs`；待核心模块完成后再评估 Vite。
